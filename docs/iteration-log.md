# 迭代记录

## 2026-10-30：提交恢复与运行包隔离

### 本轮发现与结果

1. 原页面只在内存保留未确认提交的幂等键。如果后端已经接受生成任务、响应却丢失，用户刷新后再提交同一描述会创建新任务。现在在发送前写入当前标签页的提交记录，并将请求标识放入地址；刷新先通过新增的只读查询接口找回原任务。没有查到任务时不自动重发，同一描述的手动重试继续使用原标识。记录在确认任务 ID 后清除；存储失败时不提交。没有增加界面入口。
2. 本机复现了运行中重新执行 Maven 构建后，JVM 读取被替换的 `target` JAR，触发 `NoClassDefFoundError`、HTTP 超时的问题。启动器改为从独立临时 JAR 副本运行，并在停止所有子进程后清理副本。重建包不再改变正在运行的 Java 进程所读取的文件。

### 参考与取舍

## 2026-10-30 晚间：进度查询的有限恢复

### 本轮发现与结果

原工作流只要一次进度查询抛出异常，就进入失败清理，可能取消仍在正常生成或训练的下游任务。本轮区分临时连接故障与参数、协议、格式、质量错误，只为已有任务的生成进度、重建进度、结果查询增加有限恢复：每次查询最多尝试 3 次，默认间隔 2 秒、4 秒。成功后继续原任务，连续失败才进入原有清理。

Python 适配器为网络错误和 HTTP 408/429/500/502/503/504 返回明确的临时错误码；Java 同时识别 SDK 的连接、会话与超时异常。生成、导入、启动训练和取消等写操作仍只调用一次，禁止把一次连接失败转化为第二次模型生成。退避等待每至多 100 毫秒检查取消与总超时；单次 MCP 请求仍沿用 90 秒超时，恢复不是对在途请求的即时中断。

页面沿用原来的一个输入框、一个生成按钮，只在已有进度行显示恢复状态。没有引入框架或模型依赖，没有改动免费模型选择或重建质量门槛。

### 参考与取舍

资料核对日期：2026-10-30。

- [Pydantic AI 的重试说明源码](https://github.com/pydantic/pydantic-ai/blob/main/docs/retries.md)区分传输、SDK、工作流与模型等多层重试，并说明重试次数可能相乘。本轮只在 Java 的三种只读查询上设置一层有限预算；Python 适配器与模型请求不增加重试。
- [LangGraph 的错误处理分类](https://docs.langchain.com/oss/javascript/langgraph/thinking-in-langgraph#handle-errors-appropriately)将临时网络错误与需修正输入、意外错误分开处理。落实为带类型的临时故障，而非捕获全部异常后继续运行。
- [MCP 工具错误处理规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#error-handling)区分协议错误与工具执行错误。返回格式异常、JSON-RPC 错误、工具 `isError` 不会仅凭“报错”就进入连接恢复；只有自有适配器明确标识的临时故障进入该路径。

### 验证

- 本地验证：26 项 Java、24 项 Python、4 项 Node 测试通过，原有外部 RAG 测试仍跳过。
- Java 覆盖参考图查询恢复、重建查询恢复、产物读取恢复、连续失败预算耗尽、永久错误不重试、退避中取消、总超时，以及写请求丢失响应后不重发。
- 新增真实 Java MCP SDK 连接拒绝测试，验证断开的本机端口被归类为临时故障；其他分类测试覆盖 HTTP 状态、协议、解析和返回结构。
- Python 覆盖 12 种 HTTP 状态、连接异常与坏 JSON 的区别；断言返回临时故障时也不会在适配器内部重发 POST；通过实际 FastMCP 序列化验证错误码保留。
- Playwright 使用隔离的接口替身验证恢复提示、禁止重复提交、取消与 390px 手机布局；未调用外部模型。运行环境中的两个真实 MCP 健康检查仍通过。
- 本轮没有完成真实生成图片到 3D 的质量验收。浏览器模拟状态与工作流测试替身不作为模型质量证据。

### 后续

继续以真实样例验证多视角与重建质量。若后续需要更快响应在途查询的取消，可独立评估只读调用的较短超时；本轮没有扩大生成请求的重试或费用范围。

## 2026-10-31 凌晨：重复视图提前停止

### 本轮发现与结果

开始时工作区干净，两个用户远程分支均为 `d773f40`，上一轮 CI 成功。检查发现：即便第 2 张候选图已与第 1 张完全重复，原流程仍会请求完 12 张才拒绝。回归测试先在旧实现上复现了这 10 次多余的生图调用。

现在逐张保存图片后立即检查已有的归一化像素摘要，发现重复就进入 `needs_review`，说明重复的两张位置，保留已有图片，并停止后续生图与视觉模型审核。重复集合不发布可导入清单，不进入重建，也不自动重试补图。第 2 张重复时只请求 2 张候选图，第 7 张重复时只请求 7 张。检查完全复用原有重复判定，不引入近似相似度阈值或新模型；不同像素仍不等于不同视角，更不能证明几何一致。
